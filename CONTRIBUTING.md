# Contributing to Builder Ledger

## Development Workflow

1. Pull the latest changes from the default branch.
2. Create a feature branch for your work.
3. Make focused, clearly scoped changes.
4. Build the .NET solution and run available tests.
5. Verify frontend changes locally.
6. Commit your changes with a meaningful message.
7. Push your branch and open a pull request.

## Branch Naming

Use descriptive branch names, for example:

- feature/site-management
- fix/login-validation
- docs/update-readme

## Commit Messages

Use short, action-oriented commit messages.

Examples:

- Add site validation
- Fix login error handling
- Update database setup documentation
- Refactor site repository

## Code Quality

- Follow the existing project conventions.
- Avoid committing secrets or generated files.
- Update documentation when configuration or
  setup instructions change.
- Test relevant functionality before submitting changes.
